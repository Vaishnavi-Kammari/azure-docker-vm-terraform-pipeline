# Azure DevOps -> Ubuntu VM (Docker) via SSH

```
.
├── app/compose.yaml            # httpd service (deployed by pipeline)
├── azure-pipelines.yml         # copy over SSH + docker compose up -d on every push
├── scripts/show-vm-state.sh    # optional helper to show VM state
└── terraform/
    ├── main.tf variables.tf outputs.tf providers.tf terraform.tfvars
    └── modules/
        ├── resource_group/     # reads EXISTING RG (Vaishnavi_Rg)
        ├── network/            # vnet, subnet, NSG (22, 8080-8090)
        └── compute/            # SSH key, public IP, NIC, Ubuntu 22.04 VM + Docker via cloud-init
```

## 1. Create the VM (PowerShell)
```powershell
az login
cd terraform
terraform init
terraform apply
```
- The SSH key is generated by Terraform (no `~/.ssh/id_rsa.pub` needed) and saved as `terraform/vm_key.pem`.
- Uses the existing resource group `Vaishnavi_Rg` (change in `terraform.tfvars` if the name differs).
- Note the `public_ip` output. Wait 2-3 minutes for Docker to install.

## 2. Azure DevOps
1. Push this folder to your Azure Repos repo, branch `main`.
2. Project Settings -> Service connections -> New -> **SSH**
   - Host: `<public_ip>`, Port: 22, Username: `azureuser`
   - Private key: paste the full contents of `terraform/vm_key.pem`
   - Name: **vm-ssh**
3. Pipelines -> New pipeline -> Azure Repos Git -> Existing YAML -> `/azure-pipelines.yml`
4. Approve the permission prompt on the first run.

(If Microsoft-hosted agents show "No hosted parallelism", request the free grant or use a self-hosted agent.)

## 3. Proof
Edit `app/compose.yaml`, e.g. `image: httpd:2.4.63` and port `"8081:80"` (keep 8080-8090), then:
```
git add . && git commit -m "change image/port" && git push
```
The pipeline log's last step prints `docker compose ps`, the image, port and an HTTP 200 check.
Or verify yourself: open `http://<public_ip>:8081` or run `ssh -i terraform/vm_key.pem azureuser@<ip> docker ps`.

## Cleanup
`terraform destroy` (the existing resource group is not deleted).
